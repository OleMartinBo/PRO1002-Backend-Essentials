## WR2 Run instructions
### Exercise 1. File to List Converter:
1. To run the program open "converter.py" and click "Run python file".
2. Open the "Documents" folder and right-click on progLanguages.txt.
3. Copy the relative path.
4. Paste the path into the program input field displayed in the terminal.

### Exercise 2. Task List Manager (with separate module):
1. To run the Task List Manager, open "main.py" and click "Run python file".
2. Enter whether you are adding or removing a task.
3. Type "done" when you want to quit.

### Exercise 3. Simple Class and Inheritance:
1. To call "greet()" and print the "student_id", open "main.py".
2. Modify "student1" with your desired values, ​​or create a new student object.
3. If you create a new student object, call "greet()" using "yourObject.greet()".
4. To print the "student_id", use "yourObject.print_student_id()".
5. Then click "run python file".

# Work Requirement 2 Reflection
- I think documentation is highly useful for creating and supporting a shared understanding within a development team. For me, written documentation helps me understand what has been completed or changed and provides insight into decisions made throughout a project's lifecycle. By extending written documentation with diagrams, it also becomes easier to visualize and discuss a program's structure and behavior. Therefore, both written and visual documentation play an important role in helping the team learn and share knowledge.
- Furthermore, in my experience, version control has supported smoother collaboration by making it easier to track changes, monitor project progress, and divide work. This has helped team members stay involved and informed while also receiving feedback on their contributions to the project.
- Finally, I think pair and mob programming can be beneficial because they encourage problem-solving, generate new ideas, and support more efficient knowledge sharing. Overall, I believe these practices support shared understanding and shared code ownership by involving everyone and ensuring that knowledge is shared rather than depending on a single team member.
